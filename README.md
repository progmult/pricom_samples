# Примеры кода: АИС «Приёмная комиссия» вуза

Выдержки из production-системы, которая ведёт приёмную кампанию вуза с
филиалами: подача заявлений абитуриентами, проверка сотрудниками, конкурсный
отбор, приказы о зачислении, обмен с ФИС ГИА и приёма, государственная и
внутренняя отчётность.

**Стек:** PHP, Yii 1.1, MySQL (InnoDB), MS SQL Server (учебная база вуза,
второе подключение), LDAP/Active Directory, PHPUnit.

**Масштаб:** ~820 PHP-файлов, 113 моделей, 43 контроллера, 95 миграций,
38 наборов unit-тестов на фикстурах.

## Как собран этот архив

Код в файлах — **дословный, из репозитория**, включая форматирование и отступы.
Сделано ровно три вещи:

1. Вырезаны повторяющиеся и не относящиеся к теме блоки. Каждый пропуск помечен
   строкой `/* ----- сокращено: ... ----- */`.
2. Сверху каждого файла добавлен блок-комментарий с описанием задачи и решения.
   Внутри кода мои комментарии не добавлялись — всё, что там есть, было в коде.
3. В двух файлах (`02`, `05`) фрагмент модели сопровождается объявлением класса,
   чтобы выдержка оставалась разбираемой; это помечено в тексте.

Ничего не переписано, не переименовано и не «улучшено». Любую строку можно найти
в репозитории поиском.

Из архива исключены конфигурация, реквизиты подключений, адреса серверов,
почтовые адреса и сторонние библиотеки (TCPDF, PHPRtfLite, расширения капчи и
LDAP) — только собственный код. Несколько файлов вышли на 300–350 строк: резать
дальше пришлось бы по живым методам.

## Сквозная идея

Права здесь — не «показать или скрыть кнопку», а сквозной механизм:

1. Право описано как операция и подвешено к роли (`01`), причём миграцией (`09`).
2. Роль ограничена филиалом (`02`) и конкретной записью (`01`, `05`).
3. Контроллер отсеивает грубо по экшенам и точно — по модели (`03`, `04`).
4. Смена статуса заявления **перевыдаёт роли** (`05`), поэтому «на проверке —
   не редактируется» невозможно обойти прямым POST-запросом.
5. Отчёты закрыты той же схемой и видят только свой филиал (`07`).

## Что бы сделал иначе

Код показан как есть, вместе со слабыми местами — вот они, по убыванию важности:

* **Смена статуса и перевыдача прав не в транзакции** (`05`). Между `save()`
  модели и `assign()/revoke()` в authManager есть окно, в котором статус и права
  разъезжаются. В коде на это стоит TODO. Правильно — транзакция и отдельный
  сервис переходов состояний.
* **bizRule хранится строкой PHP и выполняется через `eval`** — так устроен
  Yii 1. Не тестируется, не рефакторится IDE, не ловится статическим анализом.
  В Yii 2 это классы-правила; при переезде переписал бы туда первым делом.
* **Выбор строителя приказа деревом `if/switch`** в `Order::loadAdmissioner()`
  повторяет комбинаторику, ради развязывания которой заведены классы (`08`).
  Заменяется сборкой имени класса из свойств приказа с откатом к общему.
* **Захардкоженные значения в отчётах** (`07`): в `verifiedSql()` прямо в тексте
  запроса стоят `filial_id = 0 AND learn_year = 2017`, в ВПО-1 — границы
  отчётного периода датами. Всё это должно быть параметрами.
* **Толстые модели.** `Abit` — 2857 строк: валидация, поиск, переходы статусов,
  обмен с ФИС и печатные формы в одном классе. Разделил бы на модель, сервис
  переходов и репозиторий выгрузок.
* **Заглушка пароля для доменных учёток** (`02`): в БД пишется литерал
  `'ldappassword'`, аутентификация при этом идёт в каталоге. Работает, но такому
  значению место в конфиге, а не в коде.
* **Найденный баг** (не вошёл в архив, `RepositoryReportVPO1::r28()`): предыдущий
  год считается постфиксным декрементом `$year--`, из-за чего `:year_prev`
  получает значение текущего года; в соседнем `r29()` — корректный префиксный.
